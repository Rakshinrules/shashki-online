# Шашки на одном поле

Пробная сетевая игра для двух игроков. Статическая страница предназначена для GitHub Pages. Оба браузера видят одну партию и ходят по очереди. Встроенного компьютерного соперника и вызовов GPT API нет: GPT должен открыть ссылку второго игрока своим браузером и самостоятельно выбирать ходы в активной сессии чата.

## Как устроено

- Русские шашки, 8 × 8: обязательное взятие, бой назад, длинный ход дамки, продолжение боя после превращения, запрет повторного перепрыгивания побитой шашки.
- Перемещение двумя нажатиями: шашка → клетка. Серия взятий завершается той же шашкой.
- PeerJS 1.5.5 соединяет браузеры через WebRTC. GitHub Pages размещает файлы, а PeerJS Cloud помогает браузерам найти друг друга. Соединение не гарантировано во всех сетях; иногда необходим TURN-сервер. В этом прототипе собственный TURN не настроен.
- Оба клиента проверяют каждый ход. Номер хода и подтверждения защищают от повторной обработки. При восстановлении связи сравнивается полный журнал.
- Партия сохраняется в localStorage обоих браузеров. Она не сохраняется на GitHub. Ссылка комнаты нужна для восстановления.
- Автоматически определяются победа, троекратное повторение и 15 ходов дамками без взятий/ходов простых шашек. Специальные турнирные правила ничьей в отдельных окончаниях пока не автоматизированы.

## Публикация

Исходники подготовлены для репозитория GitHub и ветки `main`. Workflow `.github/workflows/pages.yml` запускает проверки и публикует статические файлы. В настройках репозитория Pages должен использовать GitHub Actions. Публикация из приватного репозитория зависит от тарифа GitHub.

## Партия

1. Первый игрок открывает сайт, создаёт комнату и играет белыми.
2. Ссылку «для второго игрока» получает игрок чёрными.
3. Оба держат вкладки открытыми. Ходы разрешены после сверки позиций.
4. Если чёрные вошли раньше белых, они нажимают «Подключиться снова», когда белые откроют комнату.

## Проверки

`npm test` запускает проверки правил и синхронизации без внешних зависимостей.

Локальный запуск: `python3 -m http.server 8000` из каталога проекта. Затем открыть `http://localhost:8000`.

До публикации и проверки в двух настоящих браузерах сетевой вариант следует считать непроверенным прототипом. Окончательная проверка включает: обмен двумя ходами, одинаковые позиции, повторное подключение и фактическую задержку ответа GPT.
